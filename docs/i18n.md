# Languages

Larra ships UI catalogs at the repo root under `locales/`. `en.json` is the source of truth. English, Spanish (Spain), and Catalan are maintained. Portuguese (European), French, Japanese, German, Italian, Swedish, Norwegian (Bokmål), Dutch, Czech, Greek, Danish, and Finnish share the same nested key tree and are AI-generated drafts: each of those files starts with a `_review` string asking a native speaker to run the app and fix what is off. Vite loads the same files for the webview; Rust embeds them with rust-i18n.

Menus, Settings, Chat chrome, errors, and shipped Recipe names follow the catalog. README, `docs/` (except this page), Chat/system prompts, tool descriptions, Diagnostics raw fields, and user-chosen Shelf or Recipe names stay English.

## Lookup

Svelte: `import { t } from "$lib/i18n.svelte"`, then `t("settings.title")` or `t("errors.shelfExists", { name })`. Interpolation is rust-i18n’s `%{name}` on both sides. Missing keys fall back to English, then to the key itself.

Rust: `rust_i18n::t!("menu.about")` or `t!("errors.shelfExists", name = name)`. Dynamic keys use `t!(&format!("catalog.blurbs.{slug}"))`.

Nav, View menu, and view titles translate Chat, Shelves, and Recipes with the UI. Running copy translates Shelf and Shelves with the catalog. Recipe, Chat, House rules, Online, and Larra stay English. English shipped Recipe prompts still say “this Shelf”; other catalogs use the local word.

Keep the website's plain, approachable tone, but check each string against the action it describes. Conversation attachments stay on the computer, so call them attached files. The lowest Shelf search setting still searches files: its label is Basic, although its internal value remains `off`. Personal-information labels describe the detector's actual categories; US Social Security numbers must not become local national identifiers in translation. An empty result describes what Larra could recognize, not a guarantee that a file contains no personal information.

File totals use count-neutral labels where needed. Personal-information category labels use `_one`, `_few`, and `_other`, selected with `Intl.PluralRules`. Czech needs a separate form for counts from two to four; catalogs without that distinction repeat `_other` in `_few` to keep the key tree aligned. Keep `%{variables}` unchanged and preserve `«…»` input markers in Recipe prompts. AI-assisted editing does not remove a draft catalog's `_review` note or replace a native-speaker review.

## Adding a string

1. Put the English copy in `locales/en.json` under an existing group (`menu`, `nav`, `settings`, `chat`, `errors`, …).
2. Add the same key to every other `locales/*.json` catalog. Draft catalogs stay drafts until a native speaker edits them.
3. Call `t` / `t!` from the view or the Rust command. Do not leave a hardcoded English fallback in the UI.
4. `just test` includes a key-parity check so the catalogs cannot drift. Keys that start with `_` are notes and are not part of that check.

## Locale

`settings.json` stores `uiLocale`: `system` (default) or a shipped code (`en`, `es`, `ca`, `pt`, `fr`, `ja`, `de`, `it`, `sv`, `nb`, `nl`, `cs`, `el`, `da`, `fi`). `system` uses `tauri_plugin_os::locale()` on this computer and matches a shipped catalog by language subtag (`es-MX` → `es`, `ca-ES` → `ca`, `fr-FR` → `fr`, `pt-BR` → `pt`, `no-NO` → `nb`). Changing the OS language while Larra is open has no effect until the next launch, unless Settings pins a language.

`settings_get` returns both `uiLocale` (the preference) and `resolvedLocale` (the catalog in use). The webview applies `resolvedLocale` during bootstrap, before the main window is ready. About and Update windows apply it before they mount. Changing the preference rebuilds the native menu without a restart.

Predefined menu items with no custom label follow the OS. Custom items use the catalog. Windows `&` accelerators are applied in Rust from the translated label.

## Not in the catalogs

Installer strings (`Info.plist`, NSIS/WiX) stay English for now. Right-to-left layouts are not supported. Catalogs are edited by hand; there is no `build.rs` auto-translate step.
